System One decision models — terminology — 2026-10-05

Terms used around TypeSafe AI's Jev (released 2026-09-15) and the open and commercial models that followed it. Most terms are vendor or community words a few weeks old, not settled academic terms. Where a meaning is my own inference it says so.

October 5, 2026

Why decision models

Software increasingly calls language models to make small decisions, such as routing a request, choosing a tool, or allowing an action. Language models answer in prose, so developers coax a decision out of generated text and parse it back into values their code can use, which is slow, costly, and fragile. Chat-oriented training also leaves the model's confidence unreliable, so code cannot safely act on it. Decision models fix this by changing the output and not the intelligence. The model reads the input once and returns one of the declared options with calibrated probabilities, as a value code can branch on directly. Because the options are given at call time, it keeps a language model's flexibility while costing about as little as a classifier.

Framing

  • System One model. TypeSafe's name for a model that returns a typed decision with probabilities and writes no text. It borrows Kahneman's System 1, meaning fast, intuitive judgment.
  • System Two. In this framing, the role of a language model that reasons step by step and writes text, code, or explanations.
  • Decision model (AI decision model). The generic name the wider ecosystem uses for the same class of model.
  • "LLM writes, Jev decides, code acts". The promoted division of labor. The language model plans and writes, the decision model makes the bounded choice, and ordinary code acts on the returned numbers.

Interface

  • State. The input being judged. A string, a JSON object, or an array of texts, up to 32k tokens.
  • Question (typed question, declared question). A decision written down in advance with its allowed answers. Each question is evaluated against the state in isolation, and several can run in parallel.
  • Primitives. The three question types below, which together form the whole interface.
  • Choice. Pick one of up to 255 listed options. Returns the chosen option, a probability for every option, and a confidence.
  • Score. Place the state on an ordered rubric of 2 to 10 levels. Returns the level, a probability per level, and a probability-weighted mean score. The legend is the text label of the returned level.
  • Noul. A yes/no ("is this true") question that returns one probability between 0 and 1. The word is TypeSafe's coinage. I found no stated origin.
  • what, not_for, examples. The fields that define each option or criterion. They give its meaning, the cases it should not cover, and a few sample cases.
  • Typed decision (typed output). The answer is a value from the declared set, never free text, so software uses it without parsing.
  • Confidence. A number computed from the shape of the probability distribution, not a self-report. For three options it is (3 × largest probability − 1) / 2, which is 0 when all options are equally likely and 1 when one option holds all the probability. The general form (n × largest − 1) / (n − 1) is my inference.
  • "Zero hallucinations". The guarantee that the output is always one of the declared options. TypeSafe's documentation notes that this holds by construction and is not a measured accuracy.
  • /v1/systemone. The API endpoint and request shape that many clones copy so they can replace Jev directly.

How the models are built

  • Non-autoregressive, single forward pass. The model reads the input once and produces option probabilities directly, instead of generating tokens one after another.
  • Parallel sampler. TypeSafe's undisclosed name for how Jev produces several answers in that one pass.
  • RLCD (Reinforcement Learning for Calibrated Decisions). TypeSafe's training method. It rewards calibrated probabilities using proper scoring rules such as the Brier or log score, on static labeled data rather than live environments.
  • Calibration. Stated probabilities match observed frequencies. Of all decisions given 0.9 confidence, about 90 percent should be correct.
  • ECE (expected calibration error). The average gap between stated confidence and actual accuracy across confidence bins.
  • Readout. The final step that turns the model's internal state or next-token scores into option probabilities. A "linear readout" is a single linear layer.
  • Decision head, pointer head, choice/score/noul heads. Small trained output layers on a backbone that score the options.
  • Trained versus training-free. Trained clones fine-tune a model for decisions (for example Laya, Clef, Decider, Tev1-4B). Training-free clones read decisions out of an unchanged open model (for example SemIf, LitJev, AnyJev).
  • Restricted softmax (label-token scoring, logit reading). The training-free method. Put the options in the prompt with tokens such as numbers, read the next-token probabilities on those tokens only, and renormalize them to sum to one. vLLM's allowed_token_ids does the restriction.
  • Hidden-state head. A small closed-form classifier fitted on a hidden layer partway through the model, which costs less than running the full depth (AnyJev's stronger variant).
  • Position bias, order invariance, flip rate. Position bias means the answer changes when the options are reordered. Order invariance is the absence of that. Flip rate is how often the answer changes under reordering.
  • Label prior. The model's built-in preference for certain option tokens regardless of the input. Some methods divide it out.
  • Fitted temperature (temperature scaling). A single number that sharpens or flattens the output probabilities, fitted on held-out data to improve calibration.

Using the outputs

  • Confidence gating (thresholds, escalation). Act automatically above one confidence, send to review in a middle band, and escalate to a human or a language model below it. TypeSafe's example bands are above 0.85, 0.6 to 0.85, and below 0.6.
  • "Decide high, route low". Governance decides which models are allowed per workload, and per-call routing works within that choice.
  • Router, gate, guardrail. The main jobs these models do in agent systems. A router picks a model tier or tool, a gate allows or blocks an action, and a guardrail screens inputs or outputs.
  • Selective prediction, coverage at error (Cov@ε), "auto-decidable at ≤5 percent error". The share of items the model can decide automatically while keeping its error on those items below ε. The rest are deferred.
  • AURC (area under the risk-coverage curve). One number summarizing error against coverage over all thresholds. Lower is better.
  • max_think, nothink_threshold. Settings of the reasoning variant Jeeves. The first caps the reasoning length. The second skips reasoning when the first single-pass answer is already confident enough.

Evaluation

  • JevBench. An independent public benchmark of 231 tasks in 18 families, such as multi_hop, with easy, standard, hard, and judge tiers. The hard tier holds long multi-condition policies, multi-hop lookups, traps, and deliberately ambiguous cases.
  • JevBench Score. The geometric mean of Intelligence (accuracy), Calibration, Speed, and Cost, weighted equally.
  • Jev Decision Index. A comparative leaderboard hosted on Hugging Face.

Known limits

By TypeSafe's own account, Jev does not handle multi-hop reasoning, double negatives, or arithmetic well, and its accuracy drops when the state holds unrelated content. On JevBench the multi-hop family scores between 0.33 and 0.67 across the models listed. The current fix is to add reasoning before the readout. Jeeves raises its JevBench result from Jev's 0.866 to 0.935 at a median latency of 3.3 s against about 0.3 s without reasoning.
