Robot control experiment

Metatron G1: pipeline time and action delay

Pipeline computation took 9.93 ms at the median. An added action delay of 7 ms met the test criteria; 8 ms did not.

November 7, 2026

What was measured

This note records a standalone robot simulation with no wireless or ROS data path. Two different measurements must stay separate:

  • Pipeline time: actual wall time from observation sampling to installation of the new joint targets for PD control.
  • Added action delay: deliberately imposed waiting time after inference, measured in simulation time.

Physics pauses while the model computes. The 7 ms result excludes computation from the robot’s simulation time. It is not a 7 ms limit on the complete wall-time pipeline, and it should not be added to 9.93 ms to claim a measured total delay limit.

Model and setup

  • Model: Metatron v1 G1, checkpoint G1/inference_last.ckpt, from nvidia/Metatron-v1.
  • Runtime: ProtoMotions with observation history and goal preparation, action mapping and PD control around the neural network.
  • Hardware/software: NVIDIA GeForce RTX 5090 for CUDA inference; CPU robot physics; PyTorch 2.8.0+cu128 and MuJoCo 3.5.0.
  • Scene: a simulated G1 on a 100 m course with 17 hurdles, each 0.10 m high. The 10-second trial does not require finishing the course.
  • Command: immediate 2.4 m/s, with no deliberate movement wait, speed ramp or physical standing run before measurement.
  • Duration: 10 simulated seconds per trial. Model warm-up precedes measurement; model context is reset afterward.
  • Execution: one process. The GPU was shared with other workloads rather than reserved exclusively for this test.

Robot state → observation → history and goals → Metatron → action delay queue → action mapping → PD → MuJoCo physics.

PD means proportional–derivative control: it sets joint torque using the difference between the target and current joint position, and the current joint velocity. PD is outside the Metatron neural network.

Constant action delays of 0, 1, 2, 3, 4, 5, 6, 7 and 8 ms were tested. The delay resolution was 1 ms. An action produced at simulation time 40 ms with 3 ms added delay takes effect at 43 ms; the next model call remains at 60 ms. PD keeps the previous target until a new action is released.

The reciprocal of the 9.93 ms median pipeline time is about 101 calculations per second. That is not the configured 50 Hz action frequency and does not establish a sustained real-time rate.

Pipeline delay components

With zero added action delay, 500 control cycles were timed using a monotonic wall clock. Measurement starts before observation sampling and footprint calculation and ends after the PD target is installed, before physics advances.

The first control cycle took 2,133.87 ms, including 2,129.47 ms in history, goal and input preparation. Model warm-up did not remove this first full preparation cost; its cause was not profiled further. This cycle remains in the reported statistics. The maximum among the remaining 499 cycles was 11.06 ms.

Effect of added action delay

Delay is inserted after inference and before action mapping and PD. Each trial starts from the same physical state and reset action. That action is held until the first delayed model action arrives. No packet loss or jitter is deliberately added.

The proposed passing criteria were at least 95% upright time and 90% of zero-delay progress. Forward progress is final position minus starting position toward the finish. Upright time is the fraction of observed simulation time with root height at least 0.5 m above flat ground, including startup; it is a height proxy for balance.

7 ms was the largest tested passing delay. At 8 ms, progress fell to 15.34 m and upright time to 92.91%, below both criteria. This is a result for the chosen task and criteria, not an intrinsic delay limit of Metatron.

Checks and limits

  • All 21 added-delay trials completed 10 simulated seconds. Values above 8 ms were not tested; a monotonic response is not assumed.
  • Conditions at 0, 7 and 8 ms were each repeated five times with configured seeds 17–21. Starting states and recorded trajectories were identical within each condition. These verify repeatability of one fixed setup, not robustness across different starting states.
  • A one-second comparison under identical changing actions found zero joint position and velocity difference between the original physics loop and the version allowing 1 ms action release.
  • A fresh control trial and a trial with timing enabled produced identical recorded motion: 17.48 m progress and 100% upright time. Their wall durations were 10.0669 s and 10.1386 s. The difference includes host variation and is not a separate measurement of timing overhead.
  • Release times matched requested delays. Timing records, component sums, source identity and saved recording hashes were checked.
  • The complete model, controller and random-generator state was not independently hashed. Other scenes, speeds, physical starting states and longer durations remain untested.
